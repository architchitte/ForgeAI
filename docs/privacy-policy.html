Our Core Privacy Commitment
ForgeAI is an open student application showcase designed solely for discovering and sharing student-built AI applications. We collect only what is strictly necessary for authentication and manual project publishing. We do not sell your data, perform background tracking, or scan your device.

1. Overview & Scope

This Privacy Policy describes how ForgeAI (“we”, “our”, or “the Application”) collects, stores, processes, and protects information when you install, access, or use our mobile application (Android Package: com.forgeai.app).

ForgeAI functions as a curated digital repository where university students publish application blueprints and system prompts for their AI projects, and explore blueprints published by other student creators.

2. Explicit Limitations (What ForgeAI Does NOT Do)

To ensure complete transparency and meet Google Play Store requirements, we explicitly state that:

✓ No Device Scanning

ForgeAI does not automatically scan, inspect, or access your device's files, storage, documents, photos, or personal applications.

✓ No Automated GitHub Scraping

ForgeAI does not access, crawl, or automatically collect source code from your private or public GitHub repositories.

✓ No Native Agent Execution

ForgeAI does not execute, run, or host student AI applications on ForgeAI servers. Applications run on author-hosted runtimes.

✓ No Automated AI Evaluation

ForgeAI does not perform automated AI-based evaluation, grading, scoring, or automated validation on submitted blueprints.

3. Information We Collect

We collect information through two distinct mechanisms: user authentication and manual blueprint submission.

A. Authentication Information

To create an account and verify authorized contributions, we process:

  • Email Address: Provided voluntarily via Email/Password signup or Google OAuth.
  • Display Name: Sourced from your Google profile metadata or manually updated in your user profile.
  • Profile Avatar (Optional): If authenticated via Google OAuth, the public avatar picture URL is referenced for your in-app profile.
  • Authentication Session Tokens: Cryptographically signed JWT tokens generated by Supabase Authentication to maintain active logins. Session tokens are persisted securely on your device via encrypted local SQLite storage.

B. Manually Submitted Blueprint Information

Repository entries are created only when you explicitly complete and submit the Blueprint Submission Form. ForgeAI stores the following five user-entered fields:

Field Name Description & Purpose Storage Location
App Name The title of the student AI application Public repository database
One-Liner A concise summary (max 140 characters) Public repository database
Orchestration Framework The framework used (e.g., LangGraph, CrewAI, DSPy, AutoGen) Public repository database
Complete System Prompt The operational system prompt powering the agent Public repository database
Active Deployment Runtime URL The external HTTPS link where the student agent is hosted (e.g., Streamlit, Vercel) Public repository database

When a blueprint is published, it is associated with your authenticated student email, student name, and optional university affiliation to provide proper project authorship attribution in the public repository feed.

C. Technical & Diagnostic Data

  • Network Requests: Basic IP and request headers required by Supabase API gateways to fulfill database read/write queries.
  • No Invasive Device Permissions: ForgeAI requests zero invasive Android permissions (no Camera, no Contacts, no Microphone, no Background Location, no Read External Storage).

4. Backend Architecture & Data Storage

ForgeAI uses Supabase (powered by PostgreSQL) for authentication and data management:

  • Supabase Authentication: Handles password hashing (bcrypt), token issuance, and OAuth session verification. Passwords are never stored in plaintext and cannot be read by ForgeAI administrators.
  • Supabase PostgreSQL Database: Blueprint records reside in the repositories table.
  • Row Level Security (RLS): The database enforces granular PostgreSQL Row Level Security:
    • Public Read Access: All app users can browse published blueprints in the showcase repository.
    • Authenticated Write Access: Only authenticated users with verified sessions can insert new blueprints.
    • Owner-Restricted Modifications: Users can only update or edit blueprints associated with their own verified credentials.

5. How We Use Information

We use the collected information strictly to:

  • Authenticate your identity and safeguard your account against unauthorized access.
  • Display published AI application blueprints in the public showcase feed for peer learning and review.
  • Enable users to launch external deployment runtime URLs in their device's default web browser via standard Android intents.
  • Allow authors to manage, edit, or delete their submitted blueprints.

No Data Commercialization: ForgeAI does not sell, rent, monetize, or trade your personal or project data with data brokers or advertising networks. We do not display third-party advertisements.

6. User Rights, Account Deletion & Data Retention

Under Google Play Store policies and international data protection laws (GDPR, CCPA), you retain full sovereignty over your data.

A. Deletion of Published Blueprints

You can edit or request deletion of your published blueprints directly within the application via your Profile screen or by contacting our team.

To permanently delete your user account and all associated blueprint records:
